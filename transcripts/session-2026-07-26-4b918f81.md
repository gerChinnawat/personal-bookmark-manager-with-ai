Most repos are "AI-ready" only in the sense of having a CLAUDE.md. This one has the three things that actually matter: **machine-enforced rules, verifiable claims, and a defect feedback loop.** It's in the top tier of setups I'd expect an agent to succeed in.

### What's genuinely strong

- **Rules are enforced mechanically, not just written down.** The 5-step workflow lives in a `UserPromptSubmit` hook that injects itself into every prompt — and `AI_WORKFLOW.md` §8 documents before/after evidence that the hook changed agent behavior. This is the difference between "we have guidelines" and "the guidelines fire."
- **CLAUDE.md rules are checkable, not vibes.** Each of the 8 non-negotiables is concrete enough to verify mechanically ("`ownerId` is the first parameter", "PrismaService not exported from the module", "404 never 403"). An agent can't weasel out of them, and a reviewer can grep for violations.
- **Architecture designed for AI failure modes.** The four-layer privacy enforcement (§8) means one agent mistake doesn't breach the invariant. The repository-layer rule uses *module boundaries* to make the wrong thing impossible rather than merely forbidden. The §9 "candidate defects" list pre-names exactly the bugs agents typically write (unscoped lookup by id, `jwt.decode` vs `verify`, missing second ownership check).

1. **No verification infrastructure exists yet — the biggest gap.** Everything so far protects the *process*; nothing yet protects the *code*.
