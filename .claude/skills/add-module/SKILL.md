# /add-module — scaffold a new feature module

Given a module name (e.g. `tag`, `user-preference`), create every file below **in this exact order**, then verify with `npm run build` and `npm run lint`. If the `bookmark` module (`src/database/bookmark/bookmark.repository.ts`, `prisma/schema/bookmark.prisma`) already exists, use it as the canonical reference for style; otherwise follow the templates below, which already encode the ownership rules from the root `CLAUDE.md`.

**Every model generated by this skill is owner-scoped data** — the rules in the root `CLAUDE.md` (`ownerId` never from the client, every repository method takes `ownerId` first and filters on it, cross-owner access is 404 not 403, bounded list defaults, no `ownerId` in DTOs) apply to everything this skill scaffolds. If a one-off module genuinely has no owner (rare — e.g. a shared lookup table), say so explicitly before scaffolding instead of silently dropping `ownerId`.

## Naming conventions

Derive all three cases from the module name up front:

- `kebab-name` — file/folder names, URL path segment (e.g. `user-preference`)
- `PascalName` — class names, Prisma model name (e.g. `UserPreference`)
- `camelName` — Prisma Client delegate property, variable names (e.g. `userPreference`)

## Steps

### 1. Prisma schema — `prisma/schema/<kebab-name>.prisma`

One file per entity, alongside `bookmark.prisma`. Start with the id/timestamp/`ownerId` baseline and let the user fill in real fields — don't invent business fields that weren't asked for. `ownerId` is a plain column (no `User` table, per `API_DESIGN.md`), indexed first since every query filters on it:

```prisma
model <PascalName> {
  id        String   @id @default(uuid())
  ownerId   String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([ownerId, createdAt])
  @@map("<kebab_name_plural>")
}
```

If this model has a foreign key to another owned model (e.g. `collectionId` on `Bookmark`), add that field now too — it gets a second ownership check in the manager (step 5), not a compound unique index with `ownerId` (see `API_DESIGN.md`'s bookmark/collection design for why that was rejected).

After editing the schema, run `npx prisma migrate dev --name add_<kebab_name>` (creates the migration and regenerates the client). Do this before writing the repository, since the repository needs the generated `Prisma.<PascalName>...` types.

### 2. Repository — `src/database/<kebab-name>/<kebab-name>.repository.ts`

Mirror `src/database/bookmark/bookmark.repository.ts` exactly, swapping in the new model. Every method takes `ownerId` as its **first** parameter and puts it in the `where` clause — a lookup by `id` alone is a bug per `CLAUDE.md` rule 3. `update`/`remove` use `updateMany`/`deleteMany` (not `update`/`delete`) so a mismatched `ownerId` yields a `count: 0` result instead of Prisma throwing `P2025` — the caller (service layer) turns that into a uniform 404, never leaking whether the row exists under someone else's ownership. `findAll` takes bounded pagination params so no unbounded list route can ship (`CLAUDE.md` rule 8):

```typescript
import { Injectable } from '@nestjs/common';
import { <PascalName>, Prisma } from '@prisma/client';
import { PrismaService } from '../prisma.service';

const DEFAULT_LIMIT = 25;
const MAX_LIMIT = 100;

@Injectable()
export class <PascalName>Repository {
  constructor(private readonly prisma: PrismaService) {}

  create(ownerId: string, data: Omit<Prisma.<PascalName>CreateInput, 'ownerId'>): Promise<<PascalName>> {
    return this.prisma.<camelName>.create({ data: { ...data, ownerId } });
  }

  findAll(ownerId: string, { limit = DEFAULT_LIMIT, offset = 0 }: { limit?: number; offset?: number } = {}): Promise<<PascalName>[]> {
    return this.prisma.<camelName>.findMany({
      where: { ownerId },
      take: Math.min(limit, MAX_LIMIT),
      skip: offset,
    });
  }

  findOne(ownerId: string, id: string): Promise<<PascalName> | null> {
    return this.prisma.<camelName>.findFirst({ where: { id, ownerId } });
  }

  async update(ownerId: string, id: string, data: Prisma.<PascalName>UpdateInput): Promise<<PascalName> | null> {
    const { count } = await this.prisma.<camelName>.updateMany({ where: { id, ownerId }, data });
    return count === 0 ? null : this.findOne(ownerId, id);
  }

  async remove(ownerId: string, id: string): Promise<boolean> {
    const { count } = await this.prisma.<camelName>.deleteMany({ where: { id, ownerId } });
    return count > 0;
  }
}
```

Then register it in `src/database/prisma.module.ts` — add the import and add it to both `providers` and `exports`, next to `BookmarkRepository`.

### 3. DTOs — `src/modules/<kebab-name>/dtos/<kebab-name>.dto.ts`

DTO fields must match the Prisma model fields the user actually defined in step 1 (excluding `id`/`createdAt`/`updatedAt`/**`ownerId`**, which are all server-generated — `ownerId` is never a field on any inbound DTO, per `CLAUDE.md` rule 2, since it comes only from the verified JWT). Use `class-validator` decorators. If `class-validator`/`class-transformer` aren't yet installed, install them (`npm install class-validator class-transformer`) — this is the first module needing them.

The global `ValidationPipe` must be configured with `whitelist: true, forbidNonWhitelistedProperties: true` (check `main.ts` — set it once at bootstrap if missing, don't repeat it per-DTO) so an unknown key on `PUT`/`PATCH` is rejected with 400 instead of silently dropped (`CLAUDE.md` rule 7):

```typescript
import { PartialType } from '@nestjs/mapped-types';
import { IsString } from 'class-validator';

export class Create<PascalName>Dto {
  // one property per non-generated field on the <PascalName> model, e.g.:
  // @IsString()
  // name: string;
  //
  // if this model references another owned model (e.g. collectionId), include
  // that field here — its ownership gets checked in the manager, not trusted from the client.
}

export class Update<PascalName>Dto extends PartialType(Create<PascalName>Dto) {}
```

`@nestjs/mapped-types` needs installing too if it isn't already a dependency.

### 4. Service — `src/modules/<kebab-name>/services/<kebab-name>.service.ts`

Thin wrapper over the repository — business rules that operate on a single entity live here. `ownerId` is threaded through every method. "Not found" and "found but owned by someone else" must be byte-identical (`CLAUDE.md` rule 4), so a `null`/`false` from the repository always becomes the same fixed-string `NotFoundException` — never interpolate the `id` or any field value into the message (`CLAUDE.md` rule 6):

```typescript
import { Injectable, NotFoundException } from '@nestjs/common';
import { <PascalName>Repository } from '../../../database/<kebab-name>/<kebab-name>.repository';
import { Create<PascalName>Dto, Update<PascalName>Dto } from '../dtos/<kebab-name>.dto';

const NOT_FOUND_MESSAGE = '<PascalName> not found';

@Injectable()
export class <PascalName>Service {
  constructor(private readonly <camelName>Repository: <PascalName>Repository) {}

  create(ownerId: string, dto: Create<PascalName>Dto) {
    return this.<camelName>Repository.create(ownerId, dto);
  }

  findAll(ownerId: string, pagination: { limit?: number; offset?: number }) {
    return this.<camelName>Repository.findAll(ownerId, pagination);
  }

  async findOne(ownerId: string, id: string) {
    const found = await this.<camelName>Repository.findOne(ownerId, id);
    if (!found) throw new NotFoundException(NOT_FOUND_MESSAGE);
    return found;
  }

  async update(ownerId: string, id: string, dto: Update<PascalName>Dto) {
    const updated = await this.<camelName>Repository.update(ownerId, id, dto);
    if (!updated) throw new NotFoundException(NOT_FOUND_MESSAGE);
    return updated;
  }

  async remove(ownerId: string, id: string) {
    const removed = await this.<camelName>Repository.remove(ownerId, id);
    if (!removed) throw new NotFoundException(NOT_FOUND_MESSAGE);
  }
}
```

### 5. Manager — `src/modules/<kebab-name>/managers/<kebab-name>.manager.ts`

Only add real logic here if the use case coordinates multiple services/repositories (matches the pattern documented in the project's `CLAUDE.md`). For a single-entity CRUD module with no foreign key to another owned model, the manager is a thin `ownerId`-forwarding pass-through — don't invent orchestration that isn't needed:

```typescript
import { Injectable } from '@nestjs/common';
import { <PascalName>Service } from '../services/<kebab-name>.service';
import { Create<PascalName>Dto, Update<PascalName>Dto } from '../dtos/<kebab-name>.dto';

@Injectable()
export class <PascalName>Manager {
  constructor(private readonly <camelName>Service: <PascalName>Service) {}

  create(ownerId: string, dto: Create<PascalName>Dto) {
    return this.<camelName>Service.create(ownerId, dto);
  }

  findAll(ownerId: string, pagination: { limit?: number; offset?: number }) {
    return this.<camelName>Service.findAll(ownerId, pagination);
  }

  findOne(ownerId: string, id: string) {
    return this.<camelName>Service.findOne(ownerId, id);
  }

  update(ownerId: string, id: string, dto: Update<PascalName>Dto) {
    return this.<camelName>Service.update(ownerId, id, dto);
  }

  remove(ownerId: string, id: string) {
    return this.<camelName>Service.remove(ownerId, id);
  }
}
```

**If the DTO carries a foreign key to another owned model** (e.g. `collectionId` on a bookmark-like module), the manager is where the *second* ownership check goes (`CLAUDE.md` rule 5) — the write itself is already scoped to `ownerId`, but the row it points at must also be validated as belonging to the same caller before the write proceeds:

```typescript
async create(ownerId: string, dto: Create<PascalName>Dto) {
  await this.relatedService.findOne(ownerId, dto.relatedId); // throws the same NotFoundException if not owned
  return this.<camelName>Service.create(ownerId, dto);
}
```

### 6. Controller — `src/modules/<kebab-name>/controllers/<kebab-name>.controller.ts`

Base path is `api/v1/<kebab-name>`. `ownerId` is read **only** from the verified JWT's `sub` claim via the project's `@CurrentUser()` param decorator (or equivalent — check `src/auth/` for what the auth module actually exposes; if auth hasn't been implemented yet, stop and flag it rather than reading `ownerId` from the body/query/params as a stand-in). List pagination (`limit`/`offset`) comes from query params, clamped server-side in the repository — the controller just forwards whatever the client sent:

```typescript
import { Body, Controller, Delete, Get, Param, Patch, Post, Query } from '@nestjs/common';
import { CurrentUser } from '../../../auth/current-user.decorator';
import { <PascalName>Manager } from '../managers/<kebab-name>.manager';
import { Create<PascalName>Dto, Update<PascalName>Dto } from '../dtos/<kebab-name>.dto';

@Controller('api/v1/<kebab-name>')
export class <PascalName>Controller {
  constructor(private readonly <camelName>Manager: <PascalName>Manager) {}

  @Post()
  create(@CurrentUser() ownerId: string, @Body() dto: Create<PascalName>Dto) {
    return this.<camelName>Manager.create(ownerId, dto);
  }

  @Get()
  findAll(@CurrentUser() ownerId: string, @Query('limit') limit?: number, @Query('offset') offset?: number) {
    return this.<camelName>Manager.findAll(ownerId, { limit, offset });
  }

  @Get(':id')
  findOne(@CurrentUser() ownerId: string, @Param('id') id: string) {
    return this.<camelName>Manager.findOne(ownerId, id);
  }

  @Patch(':id')
  update(@CurrentUser() ownerId: string, @Param('id') id: string, @Body() dto: Update<PascalName>Dto) {
    return this.<camelName>Manager.update(ownerId, id, dto);
  }

  @Delete(':id')
  remove(@CurrentUser() ownerId: string, @Param('id') id: string) {
    return this.<camelName>Manager.remove(ownerId, id);
  }
}
```

### 7. Module + app wiring

`src/modules/<kebab-name>/<kebab-name>.module.ts`:

```typescript
import { Module } from '@nestjs/common';
import { PrismaModule } from '../../database/prisma.module';
import { <PascalName>Controller } from './controllers/<kebab-name>.controller';
import { <PascalName>Service } from './services/<kebab-name>.service';
import { <PascalName>Manager } from './managers/<kebab-name>.manager';

@Module({
  imports: [PrismaModule],
  controllers: [<PascalName>Controller],
  providers: [<PascalName>Service, <PascalName>Manager],
})
export class <PascalName>Module {}
```

Then register it in `src/app.module.ts`: import `<PascalName>Module` and add it to the root `imports` array, next to `PrismaModule`.

## Verify

Run `npm run build` and `npm run lint` and fix anything that surfaces before considering the module done.

Per `CLAUDE.md`, the security matrix test is a precondition, not a follow-up: this module's routes must be added to the existing security matrix harness (`API_DESIGN.md` §8) in the same commit — covering cross-owner 404s, unauthenticated 401s, and (if step 5's foreign-key check applies) the "references someone else's row" case. Don't consider the module done until that coverage exists.
